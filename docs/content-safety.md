# 内容安全与隐私规则

**范围：** MVP，Issue #11  
**执行位置：** `ios/RoundtableCore` 的纯 Swift `ContentPolicy`

## 1. 决策模型

本地规则只产生三种结果：

- `allow`：未命中规则，正常继续。
- `block`：高置信度明显有害内容。用户输入不会发送给 Django；模型输出不会作为消息或结论提交。
- `flag`：命中较低置信度风险。内容可以继续，但 UI 明确显示“本地规则标记，未经模型或人工审核”。

`flag` 不是审核结论，也不代表举报已被处理。MVP 不接入服务端内容审核模型。

## 2. 规则类别

| 类别 | 典型阻止内容 | 典型标记内容 |
| --- | --- | --- |
| `dangerous` | 制作爆炸物、危险化学品或自伤工具的操作步骤 | 自伤表达、针对具体个人的暴力威胁 |
| `unlawful` | 绑架、投毒等犯罪步骤；涉及未成年人的色情内容 | 一般违法风险讨论由后续人工判断 |
| `hate` | 对受保护群体的消灭、清洗或劣等化煽动 | 侮辱性表达 |
| `sexual` | 未成年人性内容 | 成人性内容或不适宜措辞 |
| `harassment` | 无 | 侮辱、贬损和攻击性措辞 |
| `impersonation` | 以真实公众人物身份发言、冒充公众人物 | 边界模糊的角色扮演由 UI 继续禁止自定义角色 |
| `privacy` | 无 | 手机号、身份证号等明显个人标识 |

## 3. 边界与误报策略

1. 阻断规则优先匹配“操作步骤/教程 + 高风险对象”，避免因单独出现“炸弹”“自杀”等词而阻断预防、救援、新闻报道或学术讨论。
2. 高严重度内容（未成年人性内容、具体犯罪步骤、煽动性仇恨）使用 `block`；可能受语境影响的内容使用 `flag`。
3. 输入会做 Unicode 兼容归一化，并移除零宽连接符，降低简单变形绕过。
4. 规则表是有限的本地第一道过滤，不承诺覆盖所有语义变体。`flag` 的设计目的就是保留低置信度内容并透明提示，而不是伪装成完整审核。
5. 对真实公众人物只提供明确阻止，不提供克隆、冒充或自定义角色入口。三个预设 Agent 始终显示 AI 标识。
6. 用户举报与本地 `flag` 相互独立。举报只记录用户提交，不自动修改内容或生成审核结论。
7. 本地隐藏只改变本机显示，不删除服务端消息，也不改变其他设备。

## 4. 调用路径

- 新建议题：本地检查议题；`block` 时不创建圆桌。
- 用户消息：本地检查正文；`block` 时不发起 REST 请求。
- Provider 输出：本地检查纯文本或结构化消息的主张与正文；`block` 时通过 `content_policy_blocked` 关闭当前 Turn，不提交消息。
- 结论：本地检查结构化结论文本；`block` 时使用规则化降级结论，并将本地标记原因持久化；`flag` 时保留结论但显示本地标记。

## 5. 隐私边界

- API Key 只允许出现在 iOS Keychain 或直连 Provider 的请求头。
- 第三方数据提示的确认状态保存在 UserDefaults，不包含 API Key。
- 匿名会话标识保存在独立 Keychain service；旧 UserDefaults 标识会在启动时迁移并删除。
- 服务端圆桌、消息、事件、结论、用量和举报按圆桌最后活动时间保留 90 天。
- 删除圆桌会立即清理服务端关联数据和本机缓存、隐藏状态及恢复游标。
- API Key 不参与 90 天清理，只有用户主动删除 Provider 时移除。
