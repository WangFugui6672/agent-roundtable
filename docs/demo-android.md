# Android 演示录制脚本

目标是一支 **60 秒双端并排视频**：同一议题在 iOS 与 Android 上并行运行，展示同一套协议产生结构相同的讨论。若暂时只有 Android 端可用，退化为单端录屏，但要在视频描述里说明。

## 录制前准备

```bash
cp .env.example .env
docker compose up --build --detach --wait
curl http://127.0.0.1:8000/api/v1/health
```

Android 设备或模拟器连到本机后端：

```bash
adb reverse tcp:8000 tcp:8000
cd android && ./gradlew :app:assembleDebug -PbackendBaseUrl=http://127.0.0.1:8000
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

真实 Provider 演示需要在 App 内配置 Provider；没有可用 Key 时用 Mock 演示，事件确定性更强，画面更稳。

## 三个演示议题

| 议题 | 展示重点 |
| --- | --- |
| 该不该把验证周期压缩到两周？ | 三种立场的分歧与第二轮引用 |
| 预算有限时，先优化体验还是先保证功能完整？ | 用户控制：暂停、点名、插话 |
| 远程办公会降低团队协作效率吗？ | 结论卡与引用跳转 |

## 分镜（60 秒）

1. **0–8s｜双端首页并排**：两端同时显示同一批历史圆桌，交代「同一套协议、两个原生客户端」。
2. **8–20s｜同时进入同一议题**：两端并排展示参与者与第一轮发言，字幕标注「同一议题、同一协议、独立实现」。
3. **20–32s｜第二轮引用**：镜头推近 Android，展示「质疑 + 引用某位 Agent 的原观点」的消息卡。
4. **32–42s｜用户控制**：Android 点「暂停」，展示在当前发言完成后进入暂停；输入一条用户消息并点名一位 Agent，再点「继续」。
5. **42–52s｜资料库与检索**：打开资料库导入一篇 PDF，回到圆桌，展示「参考了资料库的 N 个片段」与展开后的原文。
6. **52–60s｜结论**：展示结论的四个分区与点击引用跳转；结尾定格在 README 的能力矩阵。

## 口播要点

- 一句话定位：多智能体圆桌，讨论可收敛成共识与分歧，而不是无休止的聊天。
- 技术卖点：协议文档是唯一契约；客户端直连 Provider，密钥不出设备。
- 端侧卖点：文档不出设备；嵌入与量化模型都在本机运行。
- 收尾：iOS 与 Android 各自独立实现，共用同一份协议。
