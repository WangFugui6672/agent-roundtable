# Agent Roundtable v0.2.0

第二个版本把客户端从单端扩展为双端：iOS（SwiftUI）与 Android（Kotlin + Jetpack Compose）
各自独立实现同一份 `docs/protocol.md`，并新增 Android 独有的资料库、端侧检索与端侧推理。
本版本同时发布 60 秒双端并排演示，用同一议题展示两端结构相同的讨论。

## 主要能力

- Android 原生客户端：`:app` + `:core`，`:core` 为纯 JVM 协议层，CI 不依赖模拟器即可测试。
- Android 完整圆桌闭环：创建、WebSocket 实时讨论、游标补发、去重、进程重启恢复。
- Android 用户控制：暂停（在途发言完成后生效）、继续、插话、点名、提前结束。
- Android 真实 Turn 执行：客户端组装 prompt、直连 Provider 流式生成、提交发言或 pass。
- Android 第二轮引用式互评、结论生成与展示；模型失败时规则化降级并明确标注。
- Android 资料库：PDF / TXT / Markdown 导入、文档块切分、端侧向量化检索、检索结果注入 system prompt。
- Android 端侧推理：llama.cpp + Qwen2.5 0.5B Q4_K_M，展示加载、首字延迟、解码速度与峰值内存。
- 双端共用协议：REST/WebSocket 字段不因客户端不同而分叉；密钥分别存 iOS Keychain 与 Android Keystore。
- 56 秒双端演示视频：同一议题、两个独立圆桌、同一套协议；两端均直连真实 Provider。

## Android v1 边界

- 未实现结论卡导出、消息举报、本地隐藏、关键观点、重新生成与继续追问；协议已支持，属后续切片。
- Mock 演示目前只自动运行第一轮，且不展示资料库引用；真实 Provider 不受影响。
- 端侧性能数据来自 Android 模拟器（Medium_Phone，arm64-v8a，API 37），尚未做真机标定。
- Android 缓存使用 Room 单表存 JSON；iOS 使用 SwiftData，两端字段对齐，改字段需同时更新解码器。

## 已知边界

- 真实模型调用依赖用户自己的 Provider Key、网络、额度和服务条款；服务端无法验证实际 Token 账单。
- 客户端上报 Token 只用于展示与成本观察，不是服务端计费级计量。
- 内容规则是本地有限第一道过滤，不等同于模型审核或人工审核。
- 90 天清理由 Compose 内的 Celery beat 每日调度 worker。
- 双端演示使用模拟器录制；真机性能与视觉差异不在本版本验证范围内。
